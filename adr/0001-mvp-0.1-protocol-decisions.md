# ADR 0001: MVP 0.1 protocol decisions

- **Status:** accepted
- **Decided by:** project owner, 2026-10-05
- **Applied by:** SPEC-PATCH-01 (prerequisite of LFCP-010, the MVP 0.1
  baseline)

## Context

The first rounds of spec work found gaps and contradictions in the Working
Drafts while building their tooling:

- extracting and checking the CDDL (LFCP-005);
- the vector validator (LFCP-007);
- the positive and negative vectors (LFCP-008, LFCP-009);
- the Shared Objects structural contract (LFCP-006).

Agents reported them under stable IDs and did not choose answers. The
project owner decided each one. This record lists every decision and where
it was applied.

Both specifications are Working Drafts, so the canonical documents, the
generators, the regenerated vectors, the extracted CDDL, the supplement,
the schemas and the fixtures were changed together, without errata files.
The only changed published vector values are listed under the migration
mapping's `changed` entries; everything else was added.

## Clarifications applied by SPEC-PATCH-02

- **Status:** decided by project owner, 2026-10-05. K1 is wording under N7,
  added by the orchestrator.
- **Applied by:** SPEC-PATCH-02 (baseline `mvp-0.1-baseline.2`).

Each one writes down behavior the SDK already implements and the vectors
already encode. No published vector value changed.

| ID | Decision | Sections changed | Vectors changed |

| CB1 | Map keys sort length-first, then bytewise (RFC 8949 §4.2.3), not by the §4.2.1 bytewise order | §5.2 rule 4 | none |
| CB2 | Map keys in deterministic structures are int, tstr or bstr; anything else → `MALFORMED_MESSAGE` | §5.2 | none |
| CB3 | No floating-point values, `undefined`, or simple values other than false/true/null, also inside `any` fields; violations → `MALFORMED_MESSAGE` | §5.2 | none (an optional float-in-`any` negative was skipped: the generator's encoder has no floats) |

| P2 | Principal ID mismatch → `AUTH_FAILED` in HELLO/AUTH, `MALFORMED_MESSAGE` elsewhere | §7 | none |
| K1 | Every persistent signed object has a CBOR payload, subject to the N7 check | §10.3 | none |

## Consequences

- LFCP-010 can freeze the MVP 0.1 baseline on top of this change.
- Implementations map these rejections to the codes above. Client-local
  rejections (N3, N5) never appear on the wire.
- The LFCP-006 contract fixtures now name their §74.1 diagnostic.
