# ADR 0003: MVP 0.1 protocol decisions, third batch

- **Status:** accepted
- **Decided by:** project owner, 2026-10-05
- **Applied by:** SPEC-PATCH-04 (baseline `mvp-0.1-baseline.4`)

## Context

Implementing the TypeScript SDK against `mvp-0.1-baseline.3` (ALIGN-TS-3,
LFCP-025 to LFCP-029) and the Shared Objects binding (LFCP-030, LFCP-031,
LFCP-033) left a set of questions open: the Data Epoch rules G-EP1 to G-EP6,
which ADR 0002 did not apply, rejections that named no error code, connection
limits, Shared Objects validation details and the Markdown reference grammar.
Agents reported them under stable IDs, with the provisional rule each
implementation chose, and did not choose final answers. The project owner
decided each one. This record lists every decision and where it was applied.

## Value changes

Existing vector values change only where a decision requires it:

- **KP-1**: `hpke_recipient_mismatch_KP0` now names CAROL at C3, where she
  holds `data/read` and OWNER may distribute, and is sealed to BOB with a
  fresh `ikmE`. Every §25.2 check passes, and only the HPKE open fails. Its
  description, `inputs.cose_sign1` and `derivation.mutation` change: 5 values.
- **General code rule**: `grant_escalation_C9`, `revoke_received_grant` and
  `extension_type_non_owner_C1` now expect `AUTHORIZATION_FAILED`, and
  `snapshot_sequence_zero` expects `MALFORMED_MESSAGE` (4 added values). The
  note of `extension_type_non_owner_C1` changes (1 value).
- **C1 context**: `extension_type_non_owner_C1` carries BOB's descriptor in
  `context.issuer_descriptor` (2 added values).
- **G-SC5**: the Shared Objects scenarios S04 and S08 use the §59 intent
  names (3 values).

Every one is listed, with its decision, in
[`migrations/mvp-0.1-baseline.4/value-changes.json`](../migrations/mvp-0.1-baseline.4/value-changes.json).
The three G-SC5 values also existed before the move to
`lfcp-vector-format/1`, so they are recorded in
[`migrations/vector-format-1/shared-objects-01.mapping.json`](../migrations/vector-format-1/shared-objects-01.mapping.json)
too. `scripts/check-baseline-changes.mjs` fails on any other changed or
removed value relative to `mvp-0.1-baseline.3`.

## Names chosen while applying

Two names were not fixed by the decisions and were chosen by the editor, to
match the provisional choices of the TypeScript SDK where it had one:

- the §74.1 diagnostic `CHANGE_ACTOR_MISMATCH` for SO-SEC1 (reported with
  `PROFILE_INVALID`);
- `AUTHORIZATION_FAILED` for a Route Update whose version does not advance,
  as an authority failure under the general code rule.

## Consequences

- Implementations move from `mvp-0.1-baseline.3` to `mvp-0.1-baseline.4`
  deliberately. `hpke_recipient_mismatch_KP0` changes bytes. Four negatives
  now name a code, and handlers that accepted any failure for them must
  check the code.
- The Rust and TypeScript SDKs replace their provisional G-EP rules with the
  normative ones and add the new negatives, the Ed25519 edge cases and the
  SO-SEC1 corpus negative to their vector runs.
