# ADR 0004: MVP 0.1 protocol decisions, fourth batch

- **Status:** accepted, per item (see the Status column)
- **Decided by:** G-DP1-GAP by the project owner, 2026-10-05. Every other
  item: orchestrator decision while the owner is away (owner AFK), pending
  owner review. The owner asked the orchestrator to proceed autonomously.
- **Applied by:** SPEC-PATCH-05 (baseline `mvp-0.1-baseline.5`)

## Context

The Rust reference server, the TypeScript client and its live interop
tests (LFCP-033 to LFCP-039a, LFCP-053, LFCP-056) and ALIGN-TS-4 raised
points the Working Drafts did not settle: an actor chain after a crash that
abandoned a reserved sequence, a Snapshot whose units a later cutoff
excludes, forward-compatible invitation URIs, the scope of a profile
diagnostic, recovery of a claimant's key, invalid Automerge bytes, and
what a server answers in several corner cases that both implementations
already handle the same way. This record lists every decision and where it
was applied.

## Decisions: LFCP-WIRE-01, normative

| ID | Status | Decision | Sections changed | Vectors |
| --- | --- | --- | --- | --- |
| G-DP1-GAP | Approved by the project owner | A writer links each Data Unit to its last published (queued) unit, so after an abandoned sequence `N` the unit at `N+1` names `N-1`. A receiver links a unit whose `previous` names its latest accepted unit of the actor, or is `null` while it has accepted none, across any sequence gap; the gap is a hole that never blocks and the Have Vector keeps it. A `previous` naming an unaccepted unit is still held (G-DP1); so are a non-null `previous` at sequence 1 and a `null` one after an accepted unit | §26.2 | new `chain_gap_linked_seq4` (accepted), `chain_prev_unknown_seq4` (held, `report`) |
| SNAP-EP | Orchestrator decision (owner AFK), pending owner review | Units covered by a verified, loaded Snapshot are accepted without checking their own `previous` links. When a newly learned Key Epoch puts a unit covered by a loaded Snapshot beyond its cutoff, the receiver discards the Snapshot-derived state and rebuilds from accepted units only, fetching the covered units | §19.1, §26.2, new §29.3 | none |
| INVITE-PARAMS | Orchestrator decision (owner AFK), pending owner review | Undefined invitation query parameters are ignored; a query that is not well-formed percent-encoding, a repeated `grant`, or invalid `endpoint`/`grant` values are rejected | §18.2 | new `invite_uri_unknown_parameter` (valid), `invite_uri_duplicate_grant` (rejected) |
| CLAIMANT-KP | Orchestrator decision (owner AFK), pending owner review | Joining needs no Key Package to the claimant (§73); so that a claimant can recover a lost key store, the inviter or any `key/distribute` holder SHOULD seal a Key Package of the current epoch to the claimant once it observes the claim | §18.1 | none |

## Consequences

- Implementations move from `mvp-0.1-baseline.4` to `mvp-0.1-baseline.5`
  deliberately. No vector value changes; the new `actor_chain` and
  `invite_uri` validation cases and the two corpus negatives need handlers.
- Writers link to their last published unit; receivers link across
  sequence gaps and keep the holes in their Have Vectors.
- SDKs report invalid Automerge bytes as `PROFILE_INVALID` /
  `INVALID_AUTOMERGE_BYTES`, and validate per field.
- Every item except G-DP1-GAP awaits the owner's review; a reversal would
  be a later batch with its own baseline.
